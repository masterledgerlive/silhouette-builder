HOW THIS CABINET PROVES ITSELF BASE SEPOLIA · TESTNET

  1. The game is just two files. doom.wasm is the engine and doom1.wad holds the levels, art and sound. Your browser downloads them and runs them — nothing is streamed from a server.
  2. Each file gets a fingerprint. A SHA-256 hash is a 64-character fingerprint: change one byte of the game and the fingerprint changes completely.
  3. The fingerprints are bundled into a manifest. The manifest's single summary fingerprint is the Merkle root. The bundle of game bytes was stored as a Quilt blob with its own id.
  4. The blob id + Merkle root were written on-chain. That is the seal transaction below. Once a block is confirmed nobody — including us — can edit what it says.
  5. Anyone can check. Press VERIFY NOW: your browser re-hashes the files it is about to play and reads the seal straight from the public chain. If every line is ✓ the game you play is the game that was sealed.

FREE READ

Checking proofs costs nothing. No wallet, no signature, no gas — just public RPC and the block explorer. Anyone can do it, any time.

PAID WRITE (KEY)

Writing something new on-chain — like sealing your run — costs gas. The relay's paying key covers it. It is on testnet until the mainnet relay is secured (login, rate limit, daily cap).

SEAL YOUR RUN

  1. Your run becomes a fingerprint. Every key you press (and when) plus the tic and frame counts are hashed into a run hash.
  2. The fingerprint is injected on-chain. SEAL THIS RUN sends a short payload (§DOOMPLAY§v1§RUN§…) to the inject relay, which writes it in a transaction. The relay returns the tx hash and, when it provides them, an inject id and hitch id.
  3. You get a location card. The pink button is the run's on-chain location. The card is saved in this browser, so it is still here after you close the tab. CHECK ON-CHAIN reads the tx back and confirms its data matches your payload.
