🔐 SEALED KEYS TrueKey vault

How the vault works: API keys are never stored here in plaintext. Each key is sealed client-side into an encrypted Walrus blob (NaCl secretbox, key derived from your true key). This room only lists sealed key slots — names and purposes. Revealing a key requires the true key, typed on your device, which never leaves it and is never sent anywhere.

  1. Seal: paste a key once → encrypted in your browser → ciphertext blob goes to Walrus.
  2. Slot: this room records the blob ID + purpose. The ciphertext is useless without the true key.
  3. Reveal: enter the true key → decrypted in memory only → copied, never stored.
  4. Revoke: re-seal under a new true key. Old ciphertext becomes permanently unreadable.

Design: TrueKey Vault (walrus-nest) — data reveals itself only under correct conditions, in order, to the right key.
